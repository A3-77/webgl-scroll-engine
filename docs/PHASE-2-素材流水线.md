# PHASE 2 —— 素材流水线（`npm run build-assets`）

> 目标：把 `input/*.jpg` 变成引擎可以直接渲染的素材 —— 干净背景 + 透明 PNG 主体 + 一份 manifest。
>
> 状态：**已完成并实测验证**。两张猫图分别产出 5 个主体（置信度 high）和 1 个主体（置信度 medium）。

---

## 1. 怎么用

```bash
npm run build-assets              # 默认 colorkey，处理 input/ 下所有图
npm run build-assets -- --only=scene02
npm run build-assets -- --provider=rembg        # 复杂背景（需先装 rembg）
npm run build-assets -- --provider=manual --masks-dir=input/masks
npm run build-assets:check        # 只校验产物与 manifest 是否一致（可进 CI）
npm run build-assets:selftest     # 图像算子自检（18 项）
npm run build-assets:providers    # 看有哪些 provider 可用
```

产物：

```
public/content/<场景名>/background.webp     干净底（主体已抹掉）
public/content/<场景名>/subject-NN.png      透明 PNG，已按面积降序编号
generated/content.json                      Python → TS 的契约
generated/report.html                       可视化验收报告（双击打开，图片全内联）
generated/preview-<场景名>.png              拼回校验图
```

**验收先看 `generated/report.html` 的第 ② 张图（掩码叠原图）。** 这是唯一能同时显示「抓到了什么」和「漏了什么」的视图 —— 主体 PNG 贴在棋盘底上只能看出抠出来的部分，看不出缺失。

## 2. 目录结构

```
scripts/build-assets/
├── run.mjs                   Node 入口：找 Python、校验依赖、调 pipeline.main
├── setup.mjs                 建 .venv 并装 numpy/pillow
└── pipeline/
    ├── main.py               CLI 编排 + 产物落盘 + 置信度汇总
    ├── imaging.py            纯 numpy 图像算子（连通域/形态学/盒模糊/金字塔填充/反混合）
    ├── compositor.py         羽化 alpha、透明 PNG、干净底、预览
    ├── metadata.py           manifest 的 dataclass（与 src/schema/asset.ts 对齐）
    ├── report.py             HTML 报告
    ├── selftest.py           算子自检
    └── providers/
        ├── base.py           ★ SegmentProvider 可插拔接口
        ├── colorkey.py       默认：背景色键控 + 自适应阈值 + 色度门 + 连通域 + 腰部拆分
        ├── manual.py         手工掩码 input/masks/<名字>.png
        └── rembg_provider.py 本地 ML 模型（u2net，176MB，按需注册）
```

**为什么分割在 Python 侧、排版在 TS 侧**：分割的实质是像素运算，numpy 里几十行，Node 里要么重写要么引重依赖；而「manifest → SceneConfig」必须与 `src/schema` 的类型严格一致，放 TS 里才有编译器检查。两边通过 `generated/content.json` 对接。

## 3. colorkey 的算法流程

```
① 估计背景色      从图像四边取样带取鲁棒中位数（边框一定是背景）
② 计算背景距离    dist = max_channel |img − bg|
③ 自适应阈值      用「边框带自身 dist 分布的高分位」抬升阈值
④ 色度门（按需）  背景非均匀时，补回「亮度贴背景但色度不贴」的主体区域
⑤ 形态学清理      开运算去噪 → 填洞 → 闭运算弥合裂缝
⑥ 连通域标记      run-length + 并查集
⑦ 拆分粘连主体    列占用率的"腰部"检测（含两道防误切保险）
⑧ 过滤小碎块      面积阈值
⑨ 置信度评估      对比裕度 = 主体 dist 中位数 / 实际阈值
```

### ③ 自适应阈值 —— 为什么必须有

两张图的实测差异：

| | 边框带 dist p95 | 背景是否均匀 |
|---|---|---|
| scene01（5 只猫，无缝纸） | **4** | 是 |
| scene02（1 只猫，带渐晕的影棚布） | **36** | 否 |

`scene02` 的背景**自身**从边缘到中心差了 37 个色阶（渐晕 + 布面褶皱），而全局单色模型只采到边缘那一侧的颜色。结果：**背景本身就被判成前景**。

实测对比（scene02）：

| 阈值 | 背景误报率 | 猫召回率 |
|---|---|---|
| 14（固定） | 47.95% | 89.68% |
| 20 | 24.32% | 82.50% |
| **36（自适应）** | **0.33%** | 39.75% |

自适应阈值把误报从 48% 压到 0.33%，代价是猫只召回 40% —— 于是需要 ④。

`scene01` 边框 p95=4 < 14，所以阈值不动，**行为与最初版本逐位一致**。

### ④ 色度门 —— 补回低对比主体

scene02 的猫是奶油色，被照亮的**前胸/左脸**在亮度上贴着背景。实测各区域：

| 区域 | R | G | B | R−G | G−B | **cdev** |
|---|---|---|---|---|---|---|
| 猫-前胸 | 215.8 | 195.3 | 178.8 | 20.5 | 16.5 | **21.3** |
| 猫-前腿 | 205.0 | 182.1 | 164.4 | 22.9 | 17.7 | **23.9** |
| 猫-左脸 | 191.8 | 162.3 | 146.9 | 29.5 | 15.4 | **28.9** |
| 猫-头右 | 228.2 | 209.9 | 206.2 | 18.3 | 3.7 | 14.0 |
| 背景-猫左 | 248.2 | 242.2 | 242.2 | 6.0 | 0.0 | 1.1 |
| 背景-猫上 | 253.0 | 251.7 | 251.4 | 1.3 | 0.3 | 5.8 |
| 背景-底边 | — | — | — | 9.0 | 2.0 | 3.1 |

`cdev` = 像素的**色度向量** (R−G, G−B) 到**背景色度向量**的欧氏距离。背景不是纯灰而是偏粉的灰 (7, 0)，主体是暖色毛发 (20, 17)。

**背景最大 5.8，主体弱对比区 21~29 —— 中间空得很干净。** 阈值取 8。

为什么不直接用 `G−B > 6`（更简单）：那是有方向的，冷色主体配暖色背景时会反噬。`cdev` 是向量距离，方向无关。

效果（scene02）：

| | 猫召回均值 | 背景误报均值 |
|---|---|---|
| 只用 dist | 41.6% | 0.0% |
| **+ 色度门** | **57.7%** | **0.0%** |

**色度门只在 ③ 真的触发时才启用。** 实测 scene01 在色度门的所有阈值下结果都与纯 dist 逐位一致，所以开着无害；但把启用条件与 ③ 绑定，能保证"背景干净的图"的行为逐位可复现 —— 这对回归排查很重要。

### ⑦ 腰部拆分的两道保险

腰部检测用于把「坐成一排、被阴影连成一个连通域」的多只猫切开。但它有两次真实的误切：

1. **切碎**：把毛发缝隙当分隔，主体被剁成几十块 → 段数 > 12 就不拆。
2. **切掉尾巴**：scene02 是单只猫，尾巴从身体右侧伸出去，尾巴那几列占用率低 → 被当成"两只猫之间的缝"，猫被切成 3 段、尾巴那 61px 被当"过小碎片"丢掉（主体 bbox 从 463×747 变成 398×753）。

   修法：**最大段 / 最小段面积 > 3.0 就不拆**。并排主体的面积应该量级相当（scene01 的 5 只猫比值 = 1.1），悬殊说明切到的是尾巴/耳朵/腿。

   ⚠️ 校验顺序不能反 —— 先丢碎屑**再**算面积比。反过来的话，5 只猫 + 2 个碎屑会因为碎屑把比值拉爆而整组放弃拆分（实测踩过，scene01 退化成 1 个主体）。

### ⑨ 置信度

`对比裕度 = 主体掩码上的 dist 中位数 / 实际阈值`

| 裕度 | 置信度 | 含义 |
|---|---|---|
| ≥ 2 且未触发自适应 | `high` | 主体明显区别于背景 |
| 1 ~ 2 | `medium` | 勉强分开，边缘可能不干净 |
| < 1 | `low` | **主体整体弱于阈值**（靠色度门硬捞的），不可靠 |

置信度写进 manifest，终端会集中列出非 high 的场景，报告页顶部显示警告横幅。

**存在的理由：不要静默地产出垃圾掩码。** 色键控有明确的适用边界，越界时必须让用户知道，而不是让他到渲染结果里才发现主体缺了一块。

## 4. 实测结果

### scene01（5 只猫，无缝纸背景）

```
背景色 RGB=(243,243,245)   边框带 p95=4 → 固定阈值 14
原始前景 28.35% → 1 个连通域 → 腰部拆成 5 个主体
置信度 high（对比裕度 3.79）
```

| 主体 | 尺寸 | 面积 | 中心 |
|---|---|---|---|
| subject-01 | 296×539 | 6.1% | (0.31, 0.50) |
| subject-02 | 275×492 | 5.7% | (0.86, 0.52) |
| subject-03 | 301×479 | 5.7% | (0.50, 0.53) |
| subject-04 | 278×477 | 5.6% | (0.13, 0.53) |
| subject-05 | 295×476 | 5.5% | (0.69, 0.53) |

抠图质量：边缘干净、无白晕，帽子/领带/衬衫/圆顶礼帽等配饰完整。**拼回校验图与原图肉眼无差异。**

### scene02（1 只猫，带渐晕影棚布）

```
背景色 RGB=(225,218,218)   边框带 p95=36 → 自适应阈值 36 + 色度门 cdev>8
原始前景 12.25% → 1 个主体 458×734，面积 12.0%，中心 (0.55, 0.60)
置信度 medium（对比裕度 1.58）
```

### provider 交叉验证

用 `rembg`（u2net）对 scene02 独立跑一遍，与 colorkey 结果对比：

- **掩码 IOU = 97.1%**（只在 colorkey: 1.5%，只在 rembg: 0.2%）
- colorkey 的版本**自带接触阴影**（在浅色背景上更"落地"）；rembg 的边缘更锐利、无阴影，但爪底被平切
- 耗时：colorkey 1.2s vs rembg 24s（首次还要下 176MB 模型）

结论：colorkey 足以胜任这类影棚图，rembg 作为复杂背景的升级路径可用且已验证。

## 5. 已知限制（诚实声明）

| 限制 | 表现 | 出路 |
|---|---|---|
| **阴影被并入主体** | scene01 的 5 只猫各带一条接触阴影切片，切片之间有垂直接缝 | 在浅色背景上肉眼不可见（拼回校验与原图一致）。若在深色背景上渲染会显形 → `--threshold` 调高（但实测会打碎主体）或手工掩码 |
| **背景有高频内容** | 树叶、砖墙、人群 → 金字塔填充会糊成色块 | `--provider rembg` |
| **主体与背景亮度和色度都接近** | 纯白猫趴在纯白纸上 → 无解 | `--provider rembg` |
| **主体内部有大片与背景同色的区域** | 会被挖空；`fill_holes` 只救被包住的 | 手工掩码 |
| **腰部检测只处理横向排布** | 纵向堆叠的主体拆不开 | 手工掩码 |
| **`--out` 必须在 `public/` 内** | 否则构建期直接失败（manifest 里的路径是相对 `public/` 的 URL） | 用 `public/content-v2` 这类路径 |

## 6. 踩过的坑（改这些代码前先读）

### `_box_blur_axis` 的负轴没归一化

```python
pad_width = [(r, r) if i == axis else (0, 0) for i in range(a.ndim)]
```

`axis=-1` 时 `i` 取 `0..ndim-1`，**永远不等于 −1** → padding 全为 0 → 数组根本没被 pad。

报错却极具误导性：`IndexError: index 4 is out of bounds for axis 2 with size 4`，看起来像"公式差一位"。盯着报错改了三版都没对。

最后是**一条常量图断言**定位的：`box_blur(np.full((20,30),7.0), 2)` 必须逐像素等于 7.0（edge padding 的意义就在于此）。所以有了 `selftest.py`。

顺带修掉了 `box_blur` 在 3D RGB 输入上去模糊**通道轴**的语义错误。

### `np.roll` 是环绕的

形态学里用它做窗口滑动，会让图像最左列被最右列影响 → 掩码上两只不相关的猫被标成同一连通域。改用 `np.pad(mode="edge")` + `np.take`。

### `--out` 指到 `public/` 外崩溃

`sub_path.relative_to(root / "public")` 抛 `ValueError`。现在改成**构建期主动失败**并说明理由 —— 继续跑的后果是 manifest 里写着一堆 URL、页面却全是 404，排查起来远比报错麻烦。

## 7. 下一步（PHASE 3）

`generated/content.json` 目前只是**素材清单**。接下来要做的是把它转成 `SceneConfig`：

- 背景 → 一个 `fit: 'cover'` 的远景平面
- 每个主体 → 一个 `fit: 'contain'` 的对象，位置由 `center` 推导
- z 深度与 `parallax` 由 `areaRatio` / `size` 自动推导（大的近、小的远）
- 套用 Motion Preset（float / sway / drift / breathe）让主体各自独立运动

**目标：加一张新图进 `input/` 只需重跑 `npm run build-assets`，不改任何 TS 代码。**
