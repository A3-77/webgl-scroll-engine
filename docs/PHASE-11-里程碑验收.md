# PHASE 11 —— 里程碑验收

> 把「素材 → 场景 → 滚动 → 相机 → 对象运动 → Shader 转场」这条链路
> 变成**一条命令跑完**的断言集，而不是每次手工点、肉眼判断。

---

## 一、怎么用

**浏览器里**：地址后加 `?accept=1`，结果自动打到 console。

**控制台里**（随时）：

```js
await __ACCEPTANCE__.run()     // 跑一遍，返回结构化报告并打印
```

报告是 JSON，可以直接在 MCP 的 `evaluate_script` 里调，也可以接进 CI（只要那个 CI 能开浏览器）。

> 入口只在**开发模式**挂载（`import.meta.env.DEV`）——
> 生产构建里不该有"能任意滚动页面并改渲染状态"的调试入口。

## 三、几个容易写错的检查

### 3.1 ④ 的比较基准 —— 这里踩过一次

「多对象独立运动」看起来很好测：采样 t 序列，比较各对象的轨迹。

**但"轨迹"拿哪个量？** 三种选择，只有一种是对的：

| 比什么 | 后果 |
|---|---|
| 绝对位置 | 含着 `baseX/baseY`（每个对象本来就落在不同地方）→ **"所有对象用同一条轨道"会被判成 PASS** |
| 世界位移 | = 轨道值 × `baseVisibleH`，而 `baseVisibleH` 随 z 变 → 同一条轨道在不同深度上产生不同世界位移 → **仍然判成 PASS**（实测踩过） |
| **屏幕归一化位移** | = 世界位移 / `baseVisibleH` —— 这才是**用户看到的东西**，也正是验收标准说的"看起来是独立运动" |

```ts
const dx = points.map((p) => (p[0] - points[0][0]) / vh / aspect);
const dy = points.map((p) => (p[1] - points[0][1]) / vh);
```

顺带一个有意思的推论：`屏幕位移 = 世界位移 / baseVisibleH` **正好就是轨道值本身** ——
所以这个检查本质上是在比"轨道值"，只是绕了一圈才想清楚。

### 3.2 ③ 的显示格式会骗人

跨章时 `progress` 会归零。如果只打 progress 序列：

```
0.33 → 0.71 → 0.43 → 0.67
```

看起来像"回退"（其实 0.43 已经是下一章的 progress）。所以输出要带章节号：

```
轨迹 0:0.33 → 0:0.71 → 1:0.43 → 1:0.67
```

判断逻辑本身只在**同一章节内**检查单调性 —— 这是对的，但**显示**必须让人也看得懂。

### 3.3 性能检查要能识别"页面不在前台"

后台标签页的 rAF 被节流到 1fps。直接报 `1.0 fps` 会让人去优化根本没问题的代码。

```ts
const hint = document.visibilityState !== 'visible' || !document.hasFocus()
  ? '（页面不在前台，rAF 被浏览器节流 —— 这条不算数）'
  : '';
```

### 3.4 验收不该留下副作用

③ 和 ⑥ 都要滚动页面。跑完必须滚回原位：

```ts
const savedY = window.scrollY;
// ... 滚动、采样 ...
e.scrollEngine.lenis.scrollTo(savedY, { immediate: true });
```

④ 和 ⑤ 会反复调 `applyTime()` 改渲染状态，跑完等几帧把画面交还给渲染循环。

## 五、★ 验证「验收会 FAIL」

**一个永远 PASS 的验收脚本是橡皮图章，比没有更糟** —— 它会让人以为检查过了。

所以跑完正常流程后，要**故意把它弄坏**，确认它真的会报错。做了两次：

### 测试 1：摘掉相机的推进轨道

```js
const b = __ENGINE__.composer.scenes[0];
b.config.camera.tracks = b.config.camera.tracks.filter(t => t.path !== 'position.z');
```

```
✗ ⑤  Camera 有明显空间运动
    相机 z 只走了 0.00 个单位，看不出推进
```

### 测试 2：让所有主体共用同一条轨道

```js
const shared = JSON.parse(JSON.stringify(b.layers[1].tracks));
for (let i = 2; i < b.layers.length; i++) b.layers[i].tracks = JSON.parse(JSON.stringify(shared));
```

```
✗ ④  Scene 内多个对象独立运动
    5 个对象都在动，但**屏幕位移完全相同** —— 看起来像整块平移，不是独立运动
```

两次都**只有目标项 FAIL**，其他项不受影响 —— 说明各项检查之间是独立的，
不会因为一处坏了就整体崩掉（那样也定位不到问题）。

> 测试 2 第一次跑时**没有 FAIL** —— 这就是发现 3.1 那个比较基准缺陷的过程。
> 换句话说：**"故意弄坏"这个动作本身就在帮你找检查逻辑的漏洞。**
