# 内容包契约

> 这个引擎只认一种输入：一个 `ContentPack` 对象。
> 你给它什么内容，它就渲染什么 —— 它不知道"猫"或"Shopify"是什么。
>
> 这一页讲清楚怎么写你自己的包。

---

## 0. 最快的路径

```bash
npm run new-pack dogs
```

生成 `src/content/dogs/{index.ts,site.ts}`，**生成后立刻可用**（不需要改别的地方，
因为内容包是自动发现的）。

然后：

1. 把图片放进 `input/`（文件名决定章节顺序：`scene01.jpg`、`scene02.jpg`…）
2. `npm run build-assets`
3. `npm run dev` → 访问 `?content=dogs`

改 `site.ts` 里的 `title` / `font` / `type` 就能换标题与字体。

## 1. 两种形态

### 1.1 素材驱动（推荐，也是这个引擎的主要用法）

场景由 build-assets 的 manifest 自动生成。**你不需要写任何场景配置。**

```ts
import { buildContent } from '../build';

export const pack: ContentPack = {
  id: 'dogs',
  label: 'Dogs',
  site: SITE,
  build: ({ aspect }) => buildContent({ aspect }),
};
```

`buildContent` 做了三件事：读 manifest（带会话级缓存）→ `composeContent` 自动构图 →
收集置信度提醒。这三件事每个素材驱动的包都要做，所以抽出来了。

**调构图参数**（全部旋钮见 [`PHASE-3-自动构图.md`](PHASE-3-自动构图.md)）：

```ts
build: ({ aspect }) => buildContent({
  aspect,
  dolly: -9,          // 相机推进量（负值 = 前进）
  dist: [16, 40],     // 主体到相机的距离区间 —— 纵深感的总旋钮
  heightVh: 2.5,      // 每章滚多远
}),
```

**用另一份 manifest**（一个项目里放两套素材）：

```bash
npm run build-assets -- --out public/content-dogs
```

```ts
build: ({ aspect }) => buildContent({ aspect, manifestUrl: '/content-dogs/manifest.json' }),
```

### 1.2 手写场景（需要精细控制时）

直接给 `assets` + `scenes`。参考 `src/content/shopify/` ——
它是这个形态的唯一示例，用 KTX2 压缩纹理 + GLB 蒙皮模型。

```ts
export const pack: ContentPack = {
  id: 'mine',
  label: 'Mine',
  site: SITE,
  assets: {
    'hero-bg': { path: 'content/mine/hero-bg.webp', kind: 'image' },
    'hero-model': { path: 'content/mine/hero.glb', kind: 'glb' },
  },
  scenes: [ /* SceneConfig[]，见 src/schema/scene.ts */ ],
};
```

> 两种形态**不能混用**：`build` 与 `assets`/`scenes` 二选一。
> 两个都给的话 `build` 优先。

## 2. 包契约

```ts
export interface ContentPack {
  id: string;                    // 唯一标识，也是 ?content=<id> 的值
  label: string;                 // 调试面板上显示的名字
  description?: string;          // 一句话说明
  site: SiteConfig;              // 标题 / 字体 / 排版 token / 过渡纹理
  assets?: AssetRegistry;        // ← 与 build 二选一
  scenes?: SceneConfig[];        // ←
  build?: (ctx: BuildContext) => Promise<ResolvedContent>;   // ←
  attribution?: string;          // 版权提示（可选）
}
```

**唯一的硬性约定**：`src/content/<id>/index.ts` 必须导出名为 `pack` 的对象。
`content.config.ts` 用 `import.meta.glob('../content/*/index.ts')` 自动发现，
靠的就是这个约定。

**没有注册表要改**。加一个包 = 建一个目录；删一个包 = 删一个目录，构建照常通过。

### 为什么 `build` 是函数而不是 Promise

`loadContentPack` 需要能选择"根本不加载这个包"（URL 参数指向了别的包）。
函数是懒执行的，Promise 不是 —— 写成 Promise 会让所有包在页面加载时一起跑。

### 为什么 `build` 拿到 `aspect` 而不是自己去读 `window`

构图数学依赖视口宽高比（见 [`PHASE-3-自动构图.md`](PHASE-3-自动构图.md) §3）。
由装配层传入，包就能保持**纯函数**：给定 `(manifest, aspect)` 永远同样的结果，
可以在 Node 里跑测试或做离线预览。

### `notes` 通道

`ResolvedContent.notes` 是给**非致命提醒**用的，会显示在调试面板上：

```ts
return { ...composed, notes: ['这张图的背景不是纯色，掩码可能有缺失'] };
```

**为什么不只 `console.warn`**：构建脚本早就把这类信息打出来了，但没人会去翻终端。
这和 build-assets 的"不要静默产出垃圾掩码"是同一条原则。

## 3. 站点配置

```ts
export const SITE: SiteConfig = {
  title: 'Dogs',
  font: { sans: '...', display: '...', script: '...' },
  type: { h2: {...}, h3: {...}, eyebrow: {...}, body: {...} },
  transitionTextures: { noise: 'noise', displacement: 'mudNormal' },
};
```

`font` / `type` 会被写成 CSS 变量（`--site-font-sans`、`--site-h2-size`…），
整站的字号阶梯一次性跟着变。

`transitionTextures` 是**资产 key**，不是路径 ——
引擎需要"一张噪声图 + 一张位移图"来做阈值场扰动，
但具体用哪张是美术决定（换一张噪声 = 完全不同的边界质感）。
默认用引擎自带的（`DEFAULT_TRANSITION_TEXTURES`）。

## 4. 场景契约（手写场景时才需要）

完整定义见 `src/schema/`。几个容易踩的点：

### 4.1 `offset` 是屏幕归一化坐标，不是世界坐标

```
offset[0] = 屏幕横坐标（−0.5..0.5）
offset[1] = 屏幕纵坐标（−0.5..0.5，正值朝上）
```

**与 z 无关** —— 同一个 offset 在 z=−30 和 z=−14 上落在同一个屏幕位置。
所以"按位置摆放"和"拉开 z 做视差"互不干扰。

### 4.2 `overscan` 是"屏幕高度占比"

`contain` 模式下它**就是**该对象占屏幕高度的比例。拉开 z 不会改变视觉大小。

### 4.3 `role` 要声明

```ts
{ id: 'bg', role: 'background', ... }   // 背景：opaque、不视差
{ id: 'cat-1', role: 'subject', ... }   // 主体：透明、视差
```

验收脚本靠 `role` 判断"背景是否该静止"，**不要靠 id 命名约定**。

### 4.4 三类动效必须动不同的属性路径

求值器按 `path` 覆盖，同一对象不能有两条 `position.y`：

| 动效 | 只能动 |
|---|---|
| 入场 | `opacity` |
| 持续运动 | `position.*` |
| 呼吸 | `scale.*` |

### 4.5 `opaque` 不是可选项

满幅背景**必须** `opaque: true`。否则它会落进透明渲染列表，
而透明列表在**不透明列表之后**绘制 —— 背景会盖住所有主体。
详见 `src/schema/object.ts` 的 `opaque` 注释。

## 6. 引擎不会因为你的包而改变

这条是设计约束，也是判断"某个改动该不该做"的标准：

- 引擎层（`engine/` `animation/` `schema/` `asset-pipeline/`）**不 import 任何内容**
- 内容包**不 import 引擎**（只 import schema）
- `app/` 是唯一知道"引擎 + 哪个内容包"的地方

如果你的需求**必须**改引擎才能实现，那说明内容包的表达能力不够 ——
应该扩展 schema（加一个字段），而不是在引擎里加特例。
